### 8. Решение проблемы с отсутствием запросов к API в логах
**Проблема:** В логах фронтенда не было видно запросов к бэкенду
**Решение:**
- Добавлено логирование в Vite dev server (`frontend/vite.config.ts`)
- Настроен прокси для перенаправления запросов `/api` на бэкенд
- Убедился, что запросы действительно отправляются

### 9. Исправление проблемы с добавлением источников (POST запросы не работали)
**Проблема:** POST запросы к `/api/sources/` не доходили до бэкенда
**Причина:** Браузер не мог разрешить имя `backend` (работает на хосте, не в Docker сети)
**Решение:**
- Обновлена конфигурация Vite proxy: target изменен на `backend:8000`
- Установлена переменная `VITE_API_URL` в пустую строку
- Убраны rewrite правила, чтобы сохранить префикс `/api`
- Перезапущены контейнеры

### 10. Проверка работы прокси Vite и исправление ошибки сети
- Протестированы запросы через прокси
- Убедился, что CORS настроен корректно (`backend/config.py`)
- Добавлен `redirect_slashes=False` в FastAPI app для корректной обработки путей

### 11. Диагностика ошибки фронтенда (падение/ошибка на скриншоте)
**Проблема:** `Uncaught TypeError: Cannot read properties of undefined (reading 'filter')`
**Решение:**
- Добавлена защита от undefined в `SourcesPage.tsx`:
  ```typescript
  const filteredSources = (sources || []).filter(...)
  ```
- Обновлена обработка ответа API: `setSources(response.items || [])`

### 12. Исправление проблемы отсутствия полей name и description в GET ответе API
**Проблема:** GET запрос к `/api/sources/` возвращал данные без полей `name` и `description`, хотя в базе они были
**Причина:** `PaginatedResponse` имел поле `items: List[BaseResponse]`, которое отбрасывало дополнительные поля
**Решение:**
- Преобразовал `PaginatedResponse` в generic класс в `backend/models/base.py`:
  ```python
  class PaginatedResponse(BaseModel, Generic[T]):
      items: List[T]
      ...
  ```
- Обновил импорты и аннотации в `backend/routes/sources.py` и `backend/routes/experiments.py`:
  ```python
  @router.get("/", response_model=PaginatedResponse[SourceResponse])
  ```
- Удалил отладочный код из `sources.py`

### 13. Исправление внешнего вида: sidebar перекрывает часть названия
**Проблема:** Sidebar с фиксированной позицией перекрывал заголовок "Аэродинамическая база данных"
**Решение:**
- Убрал `position: fixed` из `Sidebar.tsx`
- Изменил структуру Layout для использования стандартной flex-раскладки Ant Design

### 14. Исправление излишнего отступа между sidebar и контентом
**Проблема:** После исправления позиции sidebar появился большой отступ между sidebar и контентом
**Причина:** В `App.css` было правило `.ant-layout-content { margin-left: 250px !important; }`, которое создавало двойной отступ
**Решение:**
- Закомментировал проблемное правило в `frontend/src/App.css`
- Теперь sidebar и контент расположены вплотную друг к другу

### 15. Перезапуск фронтенда для применения изменений
- Перезапущен контейнер фронтенда: `docker-compose restart frontend`
- Проверено, что изменения CSS применяются корректно

### 16. Настройка flex-раскладки для устранения лишнего расстояния
- Убедился, что Ant Design Layout использует flexbox по умолчанию
- Sidebar имеет ширину 250px, контент занимает оставшееся пространство

## Инструкция по запуску

1. **Запуск всех сервисов:**
   ```bash
   docker-compose -f docker-compose.dev.yml up -d
   ```

2. **Доступ к приложениям:**
   - Фронтенд: http://localhost:3000
   - Бэкенд API: http://localhost:8000
   - Документация API: http://localhost:8000/docs

3. **Проверка работы:**
   - Откройте http://localhost:3000/sources
   - Убедитесь, что таблица источников загружается
   - Попробуйте добавить новый источник
   - Обновите страницу - данные должны сохраниться

## Возможные проблемы и решения

1. **Не отображаются данные после обновления страницы:**
   - Очистите кэш браузера (Ctrl+F5)
   - Проверьте консоль разработчика на наличие ошибок

2. **Sidebar все еще перекрывает контент:**
   - Убедитесь, что файл `App.css` загрузился (проверьте Network в DevTools)
   - Перезапустите фронтенд: `docker-compose restart frontend`

3. **API запросы не работают:**
   - Проверьте, что бэкенд запущен: `docker-compose ps`
   - Проверьте логи бэкенда: `docker-compose logs backend`
